# Enterprise AI Assistant

A Retrieval-Augmented Generation (RAG) assistant that answers natural-language questions grounded in the content of your own documents (demonstrated here with a sample employee handbook), instead of relying on the model's general knowledge.

## Features

- **Grounded, low-hallucination answers** — the system prompt explicitly instructs the model to answer only from retrieved context and say when it doesn't know
- **Conversational memory** — keeps the last 10 messages per `conversation_id`, so follow-up questions retain context
- **Local embeddings & vector search** — document chunks are embedded and searched entirely on your machine, so document content is never sent anywhere just to compute embeddings
- **Cloud-scale generation** — answers are generated by Google's Gemma 4 (31B), served via Ollama's cloud API
- **Simple REST interface** — a single FastAPI endpoint for chat

## Tech Stack

| Layer | Technology |
|---|---|
| API | FastAPI |
| LLM | Gemma 4 (31B) via [Ollama Cloud](https://ollama.com) |
| Embeddings | `sentence-transformers` (`all-MiniLM-L6-v2`), run locally |
| Vector store | ChromaDB (persistent, local) |
| Document parsing | PyMuPDF |

## How It Works

1. **Ingest** — `app/rag/ingestion.py` extracts text from a source PDF with PyMuPDF and splits it into overlapping chunks (500 characters, 100-character overlap).
2. **Embed** — `app/rag/embeddings.py` encodes each chunk locally with the `all-MiniLM-L6-v2` sentence-transformer model.
3. **Store** — `app/rag/vector_store.py` persists the chunk embeddings in a local ChromaDB collection.
4. **Retrieve** — on each request, `app/rag/retrieval.py` embeds the incoming question and pulls the top-3 most similar chunks from ChromaDB.
5. **Generate** — `app/main.py` builds a prompt from the system instructions, retrieved context, and recent conversation history, then sends it to Gemma 4 (31B) via Ollama Cloud for a grounded response.
6. **Serve** — the whole flow is exposed through a single `POST /chat` endpoint.

> Gemma 4 is natively multimodal (text + image). The current pipeline only ingests text extracted from PDFs — extending ingestion to scanned or image-based documents is a natural next step (see Roadmap).

## Getting Started

### Prerequisites

- Python 3.10+
- An [Ollama Cloud](https://ollama.com) account and API key

### Installation

```bash
git clone https://github.com/aryankrsaw/enterprise-ai-assistant.git
cd enterprise-ai-assistant
python -m venv venv
source venv/bin/activate   # On Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### Configuration

Create a `.env` file in the project root:

```
OLLAMA_CLOUD_MODEL_API_KEY=your_ollama_cloud_api_key
```

### Indexing a document

Ingestion currently runs as a script rather than through the API. To index the sample handbook in `app/documents/`:

```bash
python -m app.tests.test_vector_store
```

This extracts the PDF text, chunks it, embeds it, and stores it in `./chroma_db`. Swap in your own PDF path to index a different document.

### Running the API

```bash
uvicorn app.main:app --reload
```

The API is available at `http://localhost:8000` (interactive docs at `/docs`).

### Example Request

```bash
curl -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "What are the standard working hours?", "conversation_id": "demo-1"}'
```

```
│   ├── config.py          # Ollama Cloud connection settings
│   ├── constants.py       # System prompt
│   ├── model.py            # Pydantic request/response schemas
│   ├── documents/          # Source PDFs
│   ├── rag/
│   │   ├── ingestion.py     # PDF text extraction & chunking

│   │   └── retrieval.py     # Similarity search
│   └── tests/               # Verification scripts for each pipeline stage
├── requirements.txt
└── README.md
```
